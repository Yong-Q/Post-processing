# 六物种通用运行说明

支持H2O、NH3、CO2、CH4、C2H4、C2H6的纯体系LAMMPS dump（含gzip），原子列至少为id/mol/type及坐标，长度按Å处理。不启动新MD。统一入口为`analyze --species ...`和`rdf-only --species ...`；不填species的原有analyze仍保留旧水程序。

## 一条命令处理任意一种已配置分子

```bash
.venv/bin/python -m waterpost analyze \
  --species auto --input data/C2H6-T465.4-r03-rho0.4533.dump.gz \
  --output results/ethane --env-cut 8 --rdf-max 12 \
  --first-cut 6.8 --lsi-cut 7.0 --nrad 3 --lmax 3
```

`auto`从文件名`物种-T...`识别；其他命名方式用`--species C2H6`等显式指定。`first-cut`/`lsi-cut`是分析窗口，不是每种条件通用的物理常数；应依据当前中心RDF选择，例子数值不能替代检查。env-cut、rdf-max等必须小于周期盒的保守唯一镜像半径。

默认LAMMPS类型为1:C、2:H、3:N、4:O；需要时配置：

```bash
--type-map '{"1":"H","2":"O"}'
```

程序验证每个初始mol的元素组成，不能只根据类型编号猜分子。当前纯物种配置不是任意反应混合物识别器；重原子骨架的身份沿用初始mol，H则逐帧几何归属。原子排序和编号不作为化学类别输入。

## 中心、质量与对称性

| 物种 | 标准组成摩尔质量 g/mol | 固定重原子中心 | 取向观测 | 几何氢键 |
|---|---:|---|---|---|
| H2O | 18.015 | O | OH对称和的极性轴、无向平面、形状矩 | O-H...O |
| NH3 | 17.031 | N | NH对称和的极性轴、形状矩；无任意H定义的方位角 | N-H...N |
| CO2 | 44.009 | C与两个O的质量质心 | O-O无向轴、二阶形状相关；不定义有向P1 | 无供体，不适用 |
| CH4 | 16.043 | C | 无唯一轴；采用三阶内部形状相关 | 不适用 |
| C2H4 | 28.054 | 两C中点 | C-C无向轴、无向平面、形状矩 | 不适用 |
| C2H6 | 30.070 | 两C中点 | C-C无向轴、形状矩及全部等价H-C-C-H组合 | 不适用 |

质量由标准元素质量C12.011、H1.008、N14.007、O15.999求和；dump中没有提供MD实际质量表时，这属于明确的质量约定，不是反推的运行参数。真实质量/同位素不同需相应配置或扩展。文件名中的rho仅作标签，程序用实际分子中心数/盒体积算数密度，再用各物种质量换算质量密度，不把所有分子按水质量换算。

CO2有弯曲或不等C-O键长时，全重原子质心不严格等于C。报告的center_definition始终是`heavy_skeleton_com`。完整原子质量质心`com`另存。H传递时选择重原子中心有助于保持所跟踪中心身份；这不意味着一个反应前后的物质分子始终相同。

CO2两个O、同类H和C2分子的两个C均按等价原子处理。不为CH4硬选一个H作唯一朝向，也不把无向C-C/O-O轴的任意正负号当成极性。程序保留原始位点、内部几何和等变矩；有限阶不变量不是完整无损的姿态表示。

## H传递、解离和当前组成

默认`--topology-mode nearest --bond-cut 1.35`将H归属到最近的重原子，超出阈值不强制归属。当前分子必须满足目标元素数和局部配位：C2H4每C两H、C2H6每C三H。H2O/NH3/CH4分别需2/3/4个H。CO2不需要H，空H集合可正常处理。

几何骨架窗口为CO2的C-O 0.8–1.6 Å、C2的C-C 0.9–1.9 Å；这些窗口不是电子成键模型。程序记录`molecule_valid`、`heavy_valid`、H归属和原始数据；无效目标分子的标准朝向、COM、力/力矩及不变量被掩码，raw对应量仍保留。共享H的归属依赖阈值，需评估敏感性。没有把正常H传递判成必然MD错误。

重原子骨架若本身变化，初始骨架中心只是跟踪点，不再自动等于当前分子。中心RDF会记录此类计数；不能不加判断地把其c2提升为完整反应分子热力学。

## 共同的508维局部表示

默认`nrad=3,lmax=3`，所有六物种共享C/H/N/O四通道和特征顺序：

| 部分 | 维数 | 内容 |
|---|---:|---|
| 外部径向和 | 12 | 4元素×3径向基 |
| 外部环境power | 312 | 12个元素/径向通道上三角×l=0..3 |
| 内部分子shape power | 40 | 4元素上三角×l=0..3 |
| 中心shape—外部环境耦合 | 144 | 4×4元素×3径向×l=1..3 |
| 合计 | 508 | 旋转、平移、周期镜像及等价原子置换不变量 |

内部矩采用`sum r^l Y_lm`，保留内部长度信息，按阶数带长度单位；环境系数用带平滑截断的Gaussian径向基。耦合项使中心自身的朝向参与表示，不只是把周围原子做旋转平均。

`features`保留全部环境位点，包括未归属H和中间态；`molecule_only_features`只保留当前有效目标分子的邻居。无效中心不变量为NaN。二者的条件不同，不能混称同一个无条件分布。等变系数与内部矩另存，不以坐标分量直接冒充不变标量。

较高阶或甲基构象等细节可用更大lmax并结合保存的扭角和原始环境继续研究，不能声称508维穷尽所有多体信息。共用特征并不证明模型已经跨物种泛化；自由能/c1模型还要处理温度、Hamiltonian及理想项约定。

同为508维不等于物理基完全相同。跨状态/物种合并或比较前，必须统一env-cut、径向/角向阶数及通道定义；compare命令会拒绝相同维数但不同基参数的结果。六物种批处理脚本默认给所有物种使用共同env-cut=8.5 Å，first-cut/LSI等诊断窗口可分别由各自RDF选择。

这是NumPy离线特征提取器，不是已实现的可自动微分保守势或自由能网络。几何H归属、有效性掩码和骨架身份含离散选择；如果后续要对能量求力或对泛函求导，必须另外处理可微性和对应物理变量，不能把硬分组不加检查地当连续可微接口。

## 通用版输出与性质

| 输出 | 信息和性质 |
|---|---|
| environment.h5 | 中心、完整COM/raw COM、逐原子位置/ID/元素/当前owner、有效性、附着重原子、H数、内部几何、分子轴/平面、508维两套不变量、球谐等变系数、shape矩/强度、邻居表、可用力和力矩 |
| distributions.h5 | 中心距离/配位/近邻排序/LSI/packing q、三体中心角、按元素分类的内键长/键角、适用的扭角、极性或无向轴取向联合分布、平面角、适用的氢键及网络、可选周期Voronoi |
| collective.h5 | 中心结构因子、子体积粒子数/方差/三四阶累积量、两套不变量的均值/std/边缘分布、采样协方差/PCA |
| dynamics.h5 | 中心MSD/非高斯/van Hove/散射；极性轴C1/C2或无向轴C2；CH4三阶等形状相关；组成持续与瞬时统计；标量记忆/采样诊断；适用壳层和氢键生存 |
| direct_correlations.h5 | 中心g(r)的标量OZ c2、平面投影、零模及分块/尾部诊断 |
| report.json | 物种/中心/质量/密度/状态来源、参数、帧数、有效性/骨架异常计数、适用/跳过项及输入SHA256 |

注意以下统计语义：

- `packing_q`是四个近邻分子中心的几何堆积指标；对烃类不把它解释成水氢键四面体序。
- 形状相关是有限阶内部矩的归一化重叠，可能同时反映变形与转动，不等于唯一完整姿态或自动旋转扩散系数。
- 分子转动的persistent版本要求全部保存帧内组成和有效性保持；瞬时版本只要求端点有效，允许H交换。0.5 ps之间未保存的事件无法恢复。
- 原生xu/xsu/image信息存在时保存`native_unwrapped_centers`并用于MSD；否则固定盒内推断逐帧最短镜像增量。没有原生信息时无法排除隐藏的跨盒跳跃。
- 邻居/HB生存最多在每个滞后均匀取200个时间起点，保留实际origin_stride/count；“连续”仅指保存帧。氢键仅适用于H2O/NH3，并非完整反应氢键网络模型。
- 块误差不把等价H组合当独立重复。协方差和PCA使用最多10000个确定性抽样中心；均值/std/边缘分布用全部有效中心。训练预处理仍必须只在训练集拟合。
- expensive-stride控制Voronoi、packing q4/q6、适用网络；pair-stride控制当前分析入口的中心RDF。完整特征和普通几何仍逐选中帧输出。全帧RDF建议单独使用rdf-only。

## 批量与成对密度流程

```bash
.venv/bin/python batch.py --input-dir data --output-root results/all \
  --pattern '*.dump.gz' --species auto --env-cut 8 --rdf-max 12

.venv/bin/python batch.py --mode rdf-only --input-dir data \
  --output-root results/rdf --species auto --rdf-max 12 --bins 240
```

六物种验证脚本用每类r03/r01各一条：

```bash
.venv/bin/python tools/run_six_species.py --input-dir data \
  --output-root results/six --jobs 6 --phase all
```

脚本先为12条轨迹做完整RDF/OZ，再从r03中心RDF的第一个平滑峰后选择第一个可分辨极小值作分析窗口（仍需检查物理解释），然后对六条r03做完整特征/时间分析，最后每个物种内部积分相对c1。主样本和对照温度相同，**六物种之间不做c1密度积分**。未知mu时只给差值，不制造绝对c1。

可在analyze/rdf-only里用`--model-id`记录已知模型标识或哈希；c1-scan会拒绝相互矛盾的已知标识。dump没有模型信息时只能记录调用者的同Hamiltonian假设，程序不会伪造权重校验。

`--phase rdf/analysis/c1`可分阶段。`--analysis-frames 8`仅用于短测，不能冒充全帧；`--resume`复用完成且相同参数的阶段，不能把短测复用成全量结果。失败/中断的目录不覆盖，应保留证据并选择新输出目录。

## 下载

在环境中提供有权读取该记录的`ZENODO_TOKEN`，不要写入代码或提交：

```bash
.venv/bin/python tools/download_zenodo.py --record 24123911 \
  --output-dir data --species H2O NH3 CO2 CH4 C2H4 C2H6 \
  --states r03 r01 --jobs 2
```

支持断点续传并逐文件核对远程字节数和MD5；成品文件不匹配时拒绝覆盖。程序只读记录与文件，不发布或修改Zenodo记录。仓库不包含token、模型、轨迹或大HDF5结果。

## 目前边界

这里的“通用”指六种已配置纯物种共用程序并通过各自构型/真实输入检验，不是任意分子、任意混合物、无mol身份或重原子反应网络的自动识别。没有完整分子取向OZ/组分矩阵OZ、真实偶极/介电、振动谱、自由能训练和绝对c1的无依据恢复。需要新元素/同位素/分子或混合物时，应增加配置及对称性、成键、质量和验证用例。
